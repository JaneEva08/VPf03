## Задание

Собрать управляемый промпт, получить стабильный ответ модели и превратить его в небольшой полезный артефакт:

1. Выбрать бытовую мини-задачу.
2. Собрать промпт по схеме «роль → контекст → задача → формат ответа». Формат вывода — валидный JSON `{"title", "steps", "notes"}`.
3. Запустить в одном инструменте, зафиксировать модель, temperature (рекомендуют 0.2) и системные инструкции.
4. Сделать одну итерацию качества: уточнить роль **или** добавить few-shot пример. Повторить запуск с теми же параметрами.
5. Сравнить два ответа: соответствие JSON, полезность `steps`, лаконичность `notes` (до 3 тезисов).
6. Собрать артефакт: `README.md` или мини-скрипт.

## Что сделано

Задача — напоминание о приёме таблеток: пользователь пишет расписание своими словами, модель оформляет план напоминаний на день. Тестовый ввод: «Витамин D — 1 таблетка в 09:00 после еды; Магний — 1 таблетка в 21:00 перед сном». Препараты взяты безобидные и выдуманные для примера, реальные назначения в публичный репозиторий не попали.

| Требование | Где |
|---|---|
| Бытовая мини-задача | Напоминания о приёме таблеток по заданному времени |
| Промпт «роль → контекст → задача → формат» | [`prompts/v1.json`](prompts/v1.json): роль и контекст в `system`, задача и формат в `user` |
| Формат — валидный JSON | Три ключа `title`, `steps`, `notes`; шаги в виде «ЧЧ:ММ — препарат, доза, условие» |
| Инструмент, модель, параметры | Раздел «Условия запуска» ниже |
| Итерация качества | [`prompts/v2.json`](prompts/v2.json): уточнённая роль + few-shot пример |
| Сравнение двух ответов | Раздел «Прогоны», по три запуска на версию, сырые ответы в [`results/`](results/) |
| Артефакт | [`remind.py`](remind.py): запрос к модели, проверка JSON, вывод расписания; `--out` сохраняет сырой ответ, `--check` проверяет готовый ответ без ключа |

### Схема промпта

| Часть | Содержание |
|---|---|
| Роль | Помощник по организации напоминаний о приёме лекарств |
| Контекст | Не врач: не назначает препараты, не меняет дозировки и время, не даёт медицинских советов |
| Задача | Составить план напоминаний на день из расписания пользователя |
| Формат | Только JSON без пояснений и Markdown |

Ограничение «не врач» — самое важное в этом промпте: модель должна оформлять то, что дал пользователь, а не решать за него, когда и сколько принимать.

## Чем отличается от урока — и почему

1. **Свой скрипт вместо `openai_direct.py`.** Урок выбирает промпт из меню и печатает ответ для человека. `remind.py` собирает `messages` из файла версии, сохраняет сырой ответ и проверяет его схемой — результат должна читать программа.
2. **Сравниваю версии промпта, а не temperature.** Задание требует одну итерацию при тех же параметрах, поэтому temperature зафиксирована (0.2), а меняется только промпт. Каждая версия запущена трижды.
3. **Ошибки урока, которые не повторила:**
   - в итогах урока сказано «системные (Assistant) и пользовательские (User) промпты», но `system` и `assistant` — разные роли: `system` задаёт поведение, `assistant` — это ответы модели в истории, в том числе образец для few-shot. В `v2.json` обе роли использованы по назначению;
   - у новых моделей лимит длины ответа может называться `max_completion_tokens`, а не `max_tokens`. Лимит в `remind.py` не задан, длину держит формат;
   - вывод урока «грамотный промпт даёт стабильный результат независимо от temperature» подтверждён на одной паре запусков. У меня три прогона на версию и две модели — и стабильность у них разная (см. выводы).
4. **JSON вместо Markdown.** Урок показывает ответы в Markdown. Здесь ответ проверяется `json.loads` и схемой: ключи, формат шага «ЧЧ:ММ — …», не более трёх `notes`.

## Выводы

1. **Формат JSON держат обе версии на обеих моделях:** 12 из 12 ответов валидны, все `steps` полные и в нужном формате. На простой задаче разница не в валидности, а в повторяемости и в `notes`.
2. **Few-shot переносит в ответ оформление образца.** На luna v2 вернула JSON в одну строку, как в примере, и в 2 прогонах из 3 — заголовок по шаблону образца («План приёма на день: …»). На Claude v2 дала три побайтово одинаковых ответа.
3. **Пример копирует и содержание.** У Claude `notes` в v2 взяты из образца, а не выведены из ввода: тезис «принимайте строго в указанное вами время» пользователь не писал. Здесь это безопасно, но в другой задаче так можно получить чужой текст.
4. **«До 3 тезисов» luna поняла как «можно ноль».** Во всех шести ответах `notes` пустой — даже в v2, где в образце три тезиса. Формально ответ соответствует заданию, но пользы от `notes` нет. Если тезисы нужны, формат надо писать как «1–3 тезиса», а проверку в `remind.py` — требовать хотя бы один.
5. **Роль защищает от лишних советов.** Единственный выход за роль — совет о времени напоминания у Claude в v1 (P3). Luna советов не давала вовсе, потому что `notes` не заполняла.
6. **Итерация состоит из двух правок.** Я сделала уточнение роли и добавила пример сразу. Какая из них дала эффект, по этим данным сказать нельзя: нужен отдельный прогон «v1 + только пример».
7. **Выборка маленькая:** три прогона на версию, один ввод. Это иллюстрация подхода, а не статистика. Но уже видно, что один и тот же промпт на двух моделях ведёт себя по-разному, и выбор модели надо проверять так же, как сам промпт.

## Что поправила по итогам

- В `remind.py` — собственная проверка схемы: ключи, формат шага «ЧЧ:ММ — …», не более трёх `notes`. Одного `json.loads` мало: валидный JSON с неправильными ключами проходил бы.
- Флаг `--out`: скрипт сохраняет сырой ответ модели, чтобы его можно было приложить и перепроверить.
- `.gitignore` для `__pycache__/` и `.env`; ключ API передаётся только переменной окружения.

## Что не сделано

- Не измерено влияние temperature (зафиксирована 0.2 по заданию).
- Не проверены другие расписания: три и больше препаратов, одно время на два препарата, расписание «своими словами» без точного времени, пустой ввод.
- Не проверена версия с формулировкой «1–3 тезиса» (см. вывод 4).
