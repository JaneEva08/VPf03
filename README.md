# VPf03. Промпт-инжиниринг: план напоминаний о приёме таблеток

Мини-задача: пользователь пишет расписание приёма своими словами, модель возвращает **валидный JSON** с планом напоминаний.

> Модель не врач: она не назначает препараты и не меняет дозировки и время. Она только оформляет то, что указал пользователь.

## Схема промпта

| Часть | Содержание |
|---|---|
| Роль | Помощник по организации напоминаний о приёме лекарств |
| Контекст | Не врач, не даёт медсоветов, не меняет дозировки и время |
| Задача | Составить план напоминаний на день из расписания пользователя |
| Формат | Только JSON: `{"title": "...", "steps": ["ЧЧ:ММ — препарат, доза, условие"], "notes": ["до 3 тезисов"]}` |

Промпты лежат в `prompts/v1.json` и `prompts/v2.json`.

## Условия запуска

- Инструмент: Claude в облачной сессии Claude Code. Каждый прогон шёл в отдельном чистом контексте (субагент без инструментов), по 3 прогона на версию.
- Модель: Claude Sonnet.
- **Temperature: не фиксировалась.** В этом интерфейсе параметр недоступен, использовалось значение по умолчанию. Рекомендованные 0.2 заложены как значение по умолчанию в `remind.py` для запуска через API.
- Системные инструкции: см. `prompts/*.json`.
- Тестовый ввод: «Витамин D — 1 таблетка в 09:00 после еды; Магний — 1 таблетка в 21:00 перед сном».

## Итерация качества

- **v1:** базовый промпт (роль → контекст → задача → формат).
- **v2:** добавлено (а) уточнение в роль: «отвечай только валидным JSON», (б) few-shot: пример user → assistant на других препаратах (витамин C, омега-3).

Итерация сделана одна, как требует ДЗ, но состоит из двух связанных правок. Раздельно их влияние не измерялось.

## Сравнение (3 прогона на версию, сырые ответы в `results/`)

| Критерий | v1 | v2 |
|---|---|---|
| Валидный JSON (`python remind.py --check`) | 3/3 да | 3/3 да |
| Нужные ключи, формат шагов «ЧЧ:ММ — …» | 3/3 | 3/3 |
| `steps`: время, доза, условие | 3/3 полностью | 3/3 полностью |
| `notes` ≤ 3 | 3/3 | 3/3 |
| Одинаковость ответов между прогонами | разные `title` и `notes` во всех 3 | **три ответа идентичны** |
| Отклонение от роли | в одном прогоне `notes` посоветовали, когда ставить напоминание (мягкая подсказка сверх данных пользователя) | нет |

### Выводы

1. Оба варианта выдали валидный JSON. На такой простой задаче формат держится и без примера.
2. v2 заметно стабильнее: `title` и `notes` совпали во всех прогонах. Это то, что нужно для программы, которая показывает результат пользователю.
3. Цена стабильности: модель в v2 **копирует `notes` из примера**. Часть тезисов («Принимайте строго в указанное вами время») не следует из ввода пользователя. Для медицинской тематики это скорее плюс (текст проверен заранее), но надо знать: пример задаёт не только формат, но и содержание.
4. Выборка маленькая: 3 прогона, один тестовый ввод, одна модель. Это иллюстрация, а не статистика.

## Мини-скрипт

```bash
pip install openai
export OPENAI_API_KEY=...

# сгенерировать план
python remind.py --version v2 --schedule "Витамин D — 1 таблетка в 09:00 после еды; Магний — 1 таблетка в 21:00 перед сном"

# проверить готовый JSON-ответ (ключ не нужен)
python remind.py --check results/v2_run1.json
```

Скрипт собирает `messages` из `prompts/<версия>.json`, вызывает модель (по умолчанию `gpt-4o-mini`, temperature 0.2), проверяет ответ (валидный JSON, ключи, формат шагов, `notes` ≤ 3) и печатает расписание. Вызов API через `remind.py` в этой сессии не запускался, так как ключа нет. Режим `--check` и сборка сообщений проверены.

## Структура

```
prompts/v1.json, v2.json   промпты
results/*.json             сырые ответы 3 прогонов × 2 версии
remind.py                  генерация и проверка
```
